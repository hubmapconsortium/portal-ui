- Switched MUI's CSS-in-JS engine from `styled-components` to Emotion, MUI's default. This removes the `@mui/styled-engine` alias from the Vite, Storybook and TypeScript configs, the `@swc/plugin-styled-components` build plugin, and the `styled-components` and `@mui/styled-engine-sc` dependencies (the alias had drifted to `@latest`, so the app was running a 9.x styled engine against MUI 7). Emotion forwards `$`-prefixed props to the wrapped component, so `styled(Component)` calls that take styling-only `$` props now pass a shared `shouldForwardProp` helper (`js/helpers/styled`) to keep them off the DOM, and the Chip `$borderRadius` theme variant is replaced by `sx` at its three call sites.
- Fixed the fallout found while QAing the engine swap. The icons in the Data and Resources navigation drawers had collapsed to nothing: the drawer's icon slot sizes its child with `width: 100%` in a rule that ties on specificity with MUI's own `.MuiSvgIcon-root` (`width: 1em`), so under Emotion's insertion order MUI won while the slot's 8px padding still applied, leaving a 16px box with 16px of padding. That rule now carries deliberately higher specificity so it no longer depends on stylesheet order. `LabelledSectionText` filtered the wrong prop name, so its transient `$bottomSpacing` reached the DOM and React rejected it as an invalid attribute name. The global styles used kebab-case CSS property names, which styled-components accepted and Emotion warns about, and two rules used `:first-child`, which Emotion flags as unsafe; the search bar's case targets the input wrapper by class now, since `:first-of-type` there would also have matched the label. Finally, with the styled-components SWC plugin gone there are no SWC plugins left, so the build swaps `@vitejs/plugin-react-swc` for `@vitejs/plugin-react` as Vite recommends, which also drops the `@swc/core` and `@swc/helpers` pins.
